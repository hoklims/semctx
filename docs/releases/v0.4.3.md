# v0.4.3: qualified JavaScript analysis and stronger verification

Semctx 0.4.3 keeps the npm CLI and host plugins on one release identity. Bun >=1.4.0,
Codex 0.147.0 and Claude Code 2.1.229 remain the declared host baseline.

## What changes

- Setup reports expose the observed source scope, exclusions and bounded exact-path include
  proposals. A proposal does not change configuration or establish readiness.
- The opt-in `modelo-suite-static-v1` profile admits supported JavaScript ESM inputs with
  `qualified-static-v1` selection. Admission binds Git changes, retained inputs, the analyzed
  scope and fresh index evidence. Unsupported loaders, callbacks, coercions, protocol effects
  and browser code execution refuse explicitly. This is not a universal JavaScript guarantee.
- Committed-range verification recovers guards removed from the merge-base tree instead of
  letting their absence from the head index hide them. Existing rules retain their severities.
  A range that removes a guard can now return WARN or BLOCK where older versions returned PASS.
  Qualified committed ranges that remove base lines refuse until immutable base source eligibility
  and compiler inputs can be captured. Pure additions retain their existing qualification domain;
  use refreshed working-tree verification before committing a qualified replacement.
- SQLite stores bound writer contention and CLI commands reliably release their stores.
- Multicore CI smoke reports are archived separately for each OS, shard and workflow attempt.
- Documentation keeps indexing outside pre-commit hooks. Development tools, MCP SDK packages and
  GitHub Actions receive maintenance updates with regenerated runtime bundles.

The [qualification contract](../qualification/modelo-suite-static-v1.md) owns the supported
profile and its explicit refusals. Static admission does not prove runtime or business behavior.

## Install or upgrade

After the unchanged release workflow publishes and attests this version:

```bash
bunx semctx@0.4.3 install
```

Installation does not reload an active session. Open a new Codex task, or run
`/reload-plugins` in Claude Code (restart if reload fails). Roll back with the previously
published 0.4.2 through the native host mechanism, not by editing a locked cache. This is a
consumer rollback; it does not replace the immutable 0.4.3 npm version, move `stable` by hand or
prove an active session reloaded. Reopen or reload the host after a rollback as after an upgrade.

## Evidence and limits

Source tests, CI, package publication, two-host delivery and active-session loading remain
separate observations. The annotated release tag must pass the canonical gate; npm must expose
that exact commit; both immutable host payloads must pass delivery before `stable` advances.
A historical host-baseline receipt is not a receipt for this version. The declared baseline comes
from [delivery run 34664142432](https://github.com/hoklims/semctx/actions/runs/34664142432),
not a 0.4.3 delivery observation.

Publication targets (not evidence that publication already completed):
- [npm semctx 0.4.3](https://www.npmjs.com/package/semctx/v/0.4.3)
- [GitHub v0.4.3 release](https://github.com/hoklims/semctx/releases/tag/v0.4.3)
- [Public packaged demo](https://hoklims.github.io/semctx/demo/)

The demo is a three-case packaged TypeScript fixture, not a JavaScript qualification or runtime
correctness proof. Its candidate projection records the observed package version and exact runtime
digest; older observations retain their original identities. After publication, the demo must be
rerun from the exact downloaded 0.4.3 artifact before release-phase Pages evidence is published.
The page cannot turn candidate bytes or an older demo into released-artifact evidence.

Oh My Pi remains experimental and outside the two-host delivery proof. Unsupported semantic
coverage, UNKNOWN runtime effects, untested hosts and active-session loading remain explicit.
The packaged JavaScript consumer is synthetic; it does not qualify an unrelated private pipeline.
Adoption, retention and human contribution time remain NOT_MEASURED.
