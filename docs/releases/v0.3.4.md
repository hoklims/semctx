# v0.3.4: safe setup previews and recovered index routing

Semctx 0.3.4 fixes the workspace preflight used by shared installers. In 0.3.3,
`semctx setup --dry-run` still executed the real setup pipeline and could create `.semctx/`, update
`.gitignore`, scaffold semantic files and build an index. The new dry-run path performs only
read-only validation and planning.

## Install or upgrade

Semctx 0.3.4 requires Bun >=1.4.0. Pin the release when reproducibility matters:

```bash
bunx semctx@0.3.4 install
```

Plugin installation does not reload an active agent session. Open a new Codex task, or run
`/reload-plugins` in Claude Code and restart if reload fails.

## Read-only setup planning

```bash
semctx setup --dry-run --json
```

A valid plan exits 0 with `kind: "setup_plan"` and `verdict: "SETUP_PLANNED"`. It lists
`plannedChanges`, config and semantic actions, and repository selection counts. Because no index or
runtime validation runs, `index.status` is `not-run` and both `analysisReady` and `setupReady` are
`unknown`. The report intentionally has no `ok` field.

Malformed configuration, unsafe symlinks and other deterministic workspace conflicts exit non-zero
with `kind: "setup_conflict"`. The existing polyglot-on-v1 policy refusal remains
`kind: "setup_refused"`. Neither refusal repairs or rewrites the workspace.

`semctx install` now evaluates the same plan before changing a Codex or Claude installation. A
workspace conflict therefore stops the operation before any marketplace or plugin mutation.
`install --dry-run --skip-setup` keeps its existing meaning and reports the workspace as skipped.

## Index routing recovery

The Codex and Claude marketplace plugins now contain the corrected `index-control-plane` runtime
skill and its Python scripts. After an operator records a recovered Semctx index, the router reads
the host's current status verdict again before publishing a route. It also keeps host version skew
visible when one host cannot consume a build made by the other. The shared source includes
regression cases for recovery, version skew and vendor directory admission.

Plugin installation makes the skill available to new sessions. It does not install or enable
native index routing hooks. A route is usable only with those hooks configured separately and
with current provider receipts. Historical benchmark files are not release-wide efficacy evidence.

## Compatibility and limits

The npm CLI, MCP package and supported plugins advance together to 0.3.4. Generated plugin runtimes
embed the same planner and CLI behavior. The change adds new dry-run report kinds; existing real
setup reports and the MCP `semctx_setup` contract are unchanged.

The dry run establishes only deterministic facts available without writing. It does not prove that
indexing will complete, that analysis coverage will be sufficient, or that a host loaded the new
plugin. Those outcomes remain separate runtime and delivery gates. Oh My Pi support remains
**experimental**. Adoption, retention, contribution time and human comprehension remain
**NOT_MEASURED**.

## Publication evidence and rollback

The tag-driven release workflow must publish the exact reviewed commit, verify npm `gitHead`,
advance `stable`, create the GitHub Release and then prove isolated Codex and Claude installation
from that release. Until those jobs complete, 0.3.4 is only a release candidate. The public
evidence page has its own Pages promotion and may still show an earlier release; candidate source
and local tests do not replace public registry and host-delivery evidence.

For rollback, pin `semctx@0.3.3` and the immutable `v0.3.3` plugin tag. Version 0.3.3 contains the
unsafe setup dry-run behavior, so do not use its `setup --dry-run` command on a valuable checkout.
