# v0.3.4: index routing recovery across both host plugins

Semctx 0.3.4 distributes the `index-control-plane` skill to Codex and Claude Code through the
existing Semctx marketplace plugins. The skill rereads the Semctx status verdict after an operator
records a recovered index, so a previously negative verdict does not remain cached as the route's
answer. It also preserves a version-skew reason when the current host cannot consume a build made
by the other host.

## Install or upgrade

Semctx 0.3.4 requires Bun >=1.4.0:

```bash
bunx semctx@0.3.4 install
```

The command installs the version-matched plugins from the Semctx `stable` marketplace. Start a new
Codex task or reload the Claude Code plugin to see the new skill. Existing index routing hooks are
managed separately: installing Semctx exposes the skill and scripts but does not install or enable
native host hooks.

## Evidence and limits

The runtime skill and scripts are copied byte for byte into both plugin payloads by `plugin:build`,
with `plugin:check` and plugin-parity tests verifying the inventory. The shared source regression
suite covers recovery after a negative verdict, host version skew and vendor directory admission. The 0.3.4
release workflow must still verify the annotated tag, publish the same commit to npm and `stable`,
and prove installation through both hosts before delivery is claimed. These notes alone do not
establish that publication or host activation occurred.

Semctx's impact, verification and MCP contracts are unchanged. This skill can guide retrieval and
operate an already configured index control plane; it does not grant migration, deployment or
execution authority. Runtime routing needs the host's separately configured hooks and current
provider receipts. The dated benchmarks bundled with the skill are historical, not measurements
of this release on every operating system.

The [public demo](https://hoklims.github.io/semctx/demo/) is a bounded structural example.
Adoption, user time saved and cross-platform index-routing efficacy remain **NOT_MEASURED**.
Consumer state without a current receipt remains **UNKNOWN**. Oh My Pi delivery is still
**experimental** and outside the Codex/Claude stable proof. The
[tested host baseline](https://github.com/hoklims/semctx/actions/runs/34664142432) predates 0.3.4;
the 0.3.4 workflow must produce its own delivery evidence.
