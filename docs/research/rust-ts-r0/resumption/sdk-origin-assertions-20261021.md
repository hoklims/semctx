# Additional static call-declaration assertions on twelve unchanged public units

## V2 DTO bridge and portable byte custody

The prior additional assertion draft incorrectly projected the full property-access expression into the existing DTO's `callee_text` field. V2 preserves the raw TypeScript `callee_text` (`Object.defineProperty`, for example) unchanged, adds a separate raw `callee_dto` observation, and projects `expression.name.text` for actual TypeScript PropertyAccessExpression nodes (`defineProperty` in that example). Other expressions retain `expression.getText(source)`. This is an explicit public DTO bridge derived from the TS AST, never a string split or an expectation inferred from native output. Symbols, declaration coordinates/default-library flags and read joins are unchanged. The schema/version and raw observation/oracle script pins are updated. The original oracle and v1 patch remain intact.

All new SDK sources and documents are stored as UTF-8/LF. The request and package-pin JSON fixtures are pinned by SHA256 of canonical UTF-8 JSON (recursively sorted object keys, compact syntax, no newline), so LF versus CRLF formatting does not change the derivation. Raw source-code hashes still bind the actual LF oracle script bytes. The added portability witness copies only the two fixtures into LF/CRLF temporary variants and executes a fresh check for each. No original case document is normalized or modified.

The SDK comparator tests here are standalone tests on an explicitly labeled TS DTO adapter. They do not establish that current-main SDK tests are wired into the aggregate runner; root owns that integration and its verification. No native SDK query was executed for this correction.

This patch appends exactly one separately derived assertion to each of twelve existing `::base` units. It changes no source input, root, compiler option, original assertion, producer implementation, historical case document or qualification denominator. The six direct pairs are Object.defineProperty 02-01/02-05, Object.assign 01-01/01-05, Proxy.revocable 08-01/08-02, Reflect.apply 09-01/09-02, Promise.resolve 04-01/04-04 and Reflect.set 03-01/03-04, each prefixed `V3-SDK-`.

The expected JSON is generated by actually executing the installed official TypeScript 5.9.3 runtime over the exact public SDK bytes and the unchanged twelve requests from the prior public oracle. All 132 installed package files must equal the public archived package manifest. The shared SDK JSON must have SHA256 `f57257876a383d13839a94adefb42b3d40bad2e93489a0f1a5ab29f045f139e5`; it supplies 100 libraries. Each actual TS program reads 63 distinct libraries. The public cases index, scenario and input-index byte identities, selected frozen unit pointers/canonical hashes, sources and roots are verified. Compiler options realize the frozen SDK program-options string and baseline ts-symbols.ts154-163 defaults; no literal options object in the frozen input is claimed.

The complete callee-symbol declaration list of every CallExpression is projected, including the thirteenth `resolve(1)` call in the Promise callback. Each declaration uses TypeScript `getStart(source)` and `end`, never `pos`. The fields are file, start_utf16, end_utf16 and isSourceFileDefaultLibrary, renamed default_library to match the existing public DTO. Call file/start/end, DTO callee_text (AST property name for property access) and normalized symbol_name are also checked. The full TS expression remains separately inspectable in raw observations. All declarations and calls are sorted by canonical JSON, with duplicates retained; no declaration is selected by spelling. Paths are normalized through the bound request's file map and cwd into `/project/...`, with SDK paths `/sdk/lib/...`.

The comparator helper runs only after the existing request/artifact binding. It constructs an evaluation-only `_sdk_origin_assertion` from existing `calls` and `capture_probes` fields, together with the already bound request and SDK. This field is not a new producer output. Every successful reported read must join captured bytes with its exact content_id; every call/declaration source must have a successful read. Each projected declaration records the joined source_content_id. The 63-file SDK read projection includes file/content_id/size, and the separate 100-file supplied count is checked. Unknown paths, unread declarations, malformed fields and false hashes reject. Non-read probes cannot carry a content identity. This proves linkage to reported capture reads, not the absence of hidden OS reads or actual runtime execution.

`default_library` describes static typing provenance. It alone does not establish runtime origin, alias transparency, absence of shadowing/mutation or executable dependency admission. This patch makes no such inference and adds no reason expectations. No native producer observation was consulted to derive these expectations, and no native campaign is part of this patch's author proof.

## Reproduce against existing dependencies

From the repository, with the unchanged public recipe JSON, shared SDK JSON and installed TypeScript 5.9.3 available:

```text
node tools/rust-ts-r0/qualification/derive_sdk_origin_assertions.cjs --recipes <recipes.json> --sdk <shared-sdk.json> --typescript <typescript-package-directory> --repository <baseline-repository> --check docs/research/rust-ts-r0/resumption/sdk-origin-assertions-20261021.json --evidence-output <new-ts5-dto-evidence.json>
python tools/rust-ts-r0/qualification/test_sdk_origin_recipe.py -v
python tools/rust-ts-r0/qualification/check_sdk_origin_assertions.py --evidence <new-ts5-dto-evidence.json> --work-dir <fresh-comparator-only-test-directory>
```

`--output <newfile>` replaces `--check` only when intentionally deriving a separately reviewed new expected document; it refuses an existing output path. `--raw-output <newfile>` preserves the actual full-expression and AST DTO observations, with exclusive-create semantics. Check-only recipe additions are allowed, but the complete twelve request DTOs must still equal the original oracle request fixtures before TS executes. The standalone Cargo test compiles only the new comparator helper/tests with existing pinned serde_json/sha2 dependencies, locked and offline. It does not import any producer module. On Windows it needs the already installed MSVC linker/SDK in the process environment. No global configuration is changed.

The public shared SDK can be reproduced from `resumption--gap-legacy-identity-evidence` using the public fetch_evidence.py custody path: select only compiler_files from member inputs/identity-inputs.json, preserve insertion order, retain lib/lib*.d.ts, rename each to `/sdk/lib/<basename>`, and use Python default json.dumps on `{version: '5.9.3', archive_sha256: '10e108c9cf7d5f2879053dff18515fb405abf2ccef63eaaf017d9c571687a1d3', files: ...}` without an added newline. The exact f572 hash is required; no historical executable is run.
