# Supplemental T00 observations

The three separate case directories contain independently frozen public gap
witnesses. Their manifests precede the declaration-root observation extension.
The original 354 units, 51 supports and reserved corpus remain separate.

`prepare_registry.py` prepares 67 source and 25 public vector recipes.
`source_scope_addenda.prepare_addenda` prepares eight independently frozen
assignment/coercion witnesses. Preparation is disabled and makes no candidate
query. Every host requires a fresh absolute plan, actual tool/artifact hashes,
and a separate explicit execution permit through `supplement_replay.rs`.

Python prepares frozen inputs, supervises verifier subprocesses and formats
observed output. The Rust supervisor binds successful captures to requests,
SDK/source reads, native artifacts and actual consumer context. Scope,
partition, runtime-companion and working-tree admission decisions are observed
through the Rust consumers. Missing receipts and unsupported contexts stay
UNKNOWN. The standalone producer is restored without the observer feature
before its bytes are frozen.

`runtime-manifest.json` pins the actual verifier sources and public registry.
It is a source inventory, not an execution proof or a qualification decision.
Raw mismatches, process failures and unknown observations are retained. A
matching supplemental output supplies no automatic obligation or R0 credit.

Pure controls run in the existing CI job with:

```sh
python -m unittest discover -s tools/rust-ts-r0/qualification/supplement -p 'test_*.py'
```

Physical uncaptured source files are materialized separately from captured-Map
mutations. A directory recipe restores only the empty `.git` marker explicitly
created by the frozen workspace test, with pinned setup authority and a typed
receipt; the recorder did not capture an independent directory listing.

The source-component observation mode records the actual confinement refusal
without extracting outside the repository. Ownership observations include the
actual graph at each existing before/after edge-removal hash. The mixed JS/TS
consumer accepts the observed single-Program fallback only with its exact
request, SDK, roots, read provenance, mode and reason; parallel partition
consumers still require actual parallel execution.
